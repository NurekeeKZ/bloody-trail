# Investigation Mode v0.3

Режим расширяет существующий стек сцен Bloody Trail. В полицейском участке работает отдельный кабинет с семью объектами, тремя уликами и ручной доской гипотез. Новая архитектура не заменяет Exploration, GameState, SceneManager или EvidenceManager: они дополнены.

## Запуск и проверочный маршрут

Запустите `G:\bloody\bloody_trail\run.bat`. Ранее открытый процесс нужно закрыть и запустить заново. Сохранения v1/v2 читаются с миграцией в память; новая запись использует v3.

1. Начните новую игру либо продолжите в участке. Подойдите к столу с терминалом и нажмите E.
2. Происходит затемнение 0,22 с и проявление кабинета 0,22 с. При уменьшенной анимации переход мгновенный. Персонаж в это время не движется.
3. Наведите курсор на номер 02, фотоматериалы. Появятся название, подсветка и курсор-рука. Нажмите и выберите «Зафиксировать фотографию».
4. Закройте подробный осмотр через Esc. В компьютере (01) станет доступна проверка удалённых файлов. Получите метаданные.
5. В папках дел (03) сохраните поручение Соколова. Получены три разные улики; повторный сбор не меняет статистику.
6. Tab открывает инвентарь. Выберите материал и «Открыть фотографию / документ» для изображения, описания, источника, времени и связей.
7. Вернитесь в кабинет и нажмите B. Выберите карточки «Фотография трёх капель» и «Удалённые метаданные», затем «Создать / выбрать гипотезу» и «Проверить / подтвердить».
8. Появится подтверждённый предварительный вывод и голубая линия. Он устанавливает необходимость проверки оригинала, а не личность убийцы.
9. Через телефон (05) свяжитесь с Соколовым. Теперь доступен новый вопрос «Обсудить связь снимка и удаления».
10. Закройте диалог и осмотр. «Вернуться [Esc]» вернёт в тот же экземпляр Exploration с исходной позицией Никиты.

Для отрицательного сценария соедините снимок и поручение. Проверка отклонит связь с объяснением, а flags не изменятся. Связь показаний Анны с журналом охраны останется гипотезой, пока не найден независимый пропуск Вейра.

## Кабинет

| Объект | Реальное действие |
|---|---|
| Компьютер | Прочитать информацию об архиве; получить метаданные после снимка; запросить анализ N.U.R.S. после метаданных |
| Фотоматериалы | Получить фотографию трёх капель |
| Папки дел | Получить поручение Соколова |
| Доска | Открыть ручные гипотезы |
| Телефон | Диалог с Соколовым; новый вопрос зависит от подтверждённого вывода |
| Окно | Осмотреть город; текст прямо указывает, что это не улика |
| Стол | Открыть материалы дела |

Верхняя панель показывает дело, день, время суток (сюжетный слот), найденные улики и выводы. Нижняя панель: M — карта, B — доска, Tab — материалы, T — N.U.R.S., Esc — возврат. В подробном осмотре нижняя панель затемнена: сначала закройте модальное окно. На обычной карте клавиша помощника остаётся N.

## Гипотезы и защита логики

`GameState.hypotheses` хранит канонический ключ пары, ID двух улик, ID правила или null, статус pending/confirmed/rejected и объяснение. Пара не зависит от порядка выбора; повторное создание не добавляет новую запись. Нельзя связать не найденную улику или её саму с собой.

`EvidenceManager.propose` только создаёт гипотезу и не начисляет подтверждение. `evaluate` находит явное правило пары и проверяет ВСЕ requires, а не только две выбранные карточки. Если дополнительных источников нет, объясняет, чего не хватает. Неподдерживаемая пара отклоняется. `reject` позволяет отложить непроверенную гипотезу, которую можно проверить заново; не отменяет факты уже подтверждённой цепочки.

| Пара | Дополнительные основания | Результат |
|---|---|---|
| photo + metadata | Нет | initial_anomaly: предварительный вывод и новый вопрос Соколову |
| photo + blood | Нет | pattern: совпадение следов |
| metadata + archive | sigma | history: связь с делом 2020 и «Сигмой» |
| anna + transit | pass | route: подтверждённый маршрут |
| pass + server | archive, sigma | identity: финальная цепочка действий Вейра |

`initial_anomaly` помечен optional: не заменяет четыре исходные обязательные цепочки и не является новым способом получить концовку. Финальный выбор доступен только в порту при всех обязательных flags И соответствующих уликах. N.U.R.S. по-прежнему может проверять собранные материалы автоматически; ложная ручная связь не даёт ему права обходить эти условия.

В карточках хранятся статические id/title/text/image/source в evidence.json и динамические day/slot/verified/related в GameState.evidence_records. При подтверждении независимые источники связываются взаимно. В UI verified означает участие в проверенной цепочке, а не универсальную достоверность любого толкования улики.

## Фон и изображения

Отдельный скриншот комнаты в сообщении не был доступен. Кабинет построен по перечисленным пользователем объектам и ранее прочитанной концепции Bloody Trail. Исходный код временной пиксельной иллюстрации — `src/ui/investigation_art.py`; PNG — `assets/rooms/station.png`. Графика не копирует персонажей или UI чужой игры.

Фотографии и документы в `assets/evidence/` — схематичные игровые реконструкции, а не финальный художественный комплект. Об этом написано в карточке. Тексты улик основаны на GCD: снимок трёх капель, удалённые метаданные, ключ 2/2, дело Волковых 2020, реестр «Сигмы», Анна, пропуск Вейра и серверная копия. Предварительная связь снимка/метаданных и реплики Соколова — сценарное дополнение этого прототипа; команда должна утвердить их при финальной редактуре.

Для замены фона сохраните новую иллюстрацию размером 1280×720 по пути `assets/rooms/station.png` либо измените `background` у station в `src/data/investigations.json`. Действия и условия остаются в JSON. Если композиция другая, измените только rect соответствующих hotspots. Ресурсы загружаются от корня проекта, а не текущего каталога. Если фон отсутствует, renderer=office включает процедурную резервную иллюстрацию.

```json
{
  "id": "computer",
  "label": "Компьютер N.U.R.S.",
  "rect": [365, 300, 235, 170],
  "description": "Полицейский терминал",
  "actions": [
    {"id": "deleted", "label": "Проверить удалённые файлы", "type": "collect", "evidence": "metadata", "requires": ["photo"]}
  ]
}
```

Типы действий: read, collect, board, inventory, dialogue, assistant. read показывает text; dialogue использует ID разговора; assistant запускает проверку собранных источников. requires содержит ID улик, requires_flags — ID выводов. Координаты hotspots — в логической системе 1280×720, рабочая область y=106…649. Новые зоны добавляются без изменения Investigation.

`tools/build_data.py` восстанавливает стартовые JSON и вызывает `tools/investigation_content.py`; это перезапись данных, а не обязательный шаг запуска. `tools/build_investigation_assets.py` заново создаёт временные PNG; не запускайте его поверх финальных авторских иллюстраций без намерения их заменить.

## Проверка v0.3

Команды из папки проекта:

```powershell
& G:\bloody\.venv\Scripts\python.exe -m unittest discover -s tests -v
& G:\bloody\.venv\Scripts\python.exe main.py --smoke
& G:\bloody\.venv\Scripts\python.exe -m compileall -q src tools
```

Результат: 49 тестов проходят, включая 12 новых в `tests/test_investigation.py`. Предыдущие тесты адаптированы к модальному осмотру, временному переходу и необязательному пятому выводу, сохранив проверки всех четырёх обязательных цепочек и трёх финалов. Новые тесты проверяют полный цикл до нового вопроса NPC, запрет повторного получения, условия действий, неверные/неполные пары, повторную проверку, защиту от поддельного подтверждения при загрузке, v2-миграцию, возврат позиции, hover и замену фона.

Smoke рендерит 24 экрана, включая кабинет, подробный компьютер, фотоснимок, документ, подтверждённую доску и разблокированный диалог. Они просмотрены на изображениях 1280×720. Интеграционные проверки отправляют Pygame-события в dummy SDL; это не полное ручное прохождение на физической клавиатуре. Нативный курсор в dummy SDL не создаётся: тест проверяет запрошенный тип; в обычном окне используется системный курсор-рука.

Сохранения пользователя при тестах не меняются. Версия v3 проверяет, что подтверждённая гипотеза соответствует реальному правилу и собранным источникам. При загрузке v1/v2 журнал гипотез пуст, а связанные источники восстанавливаются из уже подтверждённых правил.
