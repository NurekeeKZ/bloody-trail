# Архитектура Bloody Trail

Дополнение версии 0.2: существующий SceneManager сохранён. Добавлены Results/GameOver и вспомогательные сцены настроек, загрузки, DLC и тренировки QTE. SettingsManager хранит предпочтения отдельно; AudioManager синтезирует UI-звуки. Game управляет отдельными авто/ручным/checkpoint слотами через тот же SaveManager, считает play_seconds и рисует fade. Сохранения версии 1 читаются с нулевым временем. Детали UI: [ЛР №9](lab09/ui_ux_prototype.md).

`main.py` только разбирает CLI и запускает `Game`. Game создаёт службы, состояние, рендер, цикл событий и сценовый стек. SceneManager поддерживает replace/push/pop: осмотр и окна кладутся поверх существующего Exploration, поэтому Player и Camera не пересоздаются при возврате. Обновляется только верхняя сцена; движение под интерфейсом невозможно.

Player движется по нормализованному вектору с отдельным разрешением столкновений по осям и мелкими шагами против туннелирования. Camera использует экспоненциальное сглаживание и ограничение размером мира. InteractionSystem вычисляет расстояние до ближайшей точки объекта, проверяет преграды и выбирает только один ближайший объект в радиусе 82 пикселей.

GameState не зависит от Pygame и интерфейса. EvidenceManager и DialogueManager работают с состоянием и JSON. NLP-классификатор не импортирует игровые сцены и возвращает только интент. SaveManager проверяет версию, схему, диапазоны и основания выводов; записывает временный файл и заменяет слот. Game дополнительно проверяет коллизии позиции и доступность локации при загрузке. Ошибки показываются в игре, исходный файл при неудачной загрузке не перезаписывается.

UI и Art отвечают только за отображение. Scene-классы связывают события с менеджерами. Зависимости направлены от Game/сцен к сервисам; сервисы не импортируют Game. Межсценовые переходы используют локальные импорты, чтобы не создавать циклическую загрузку модулей.

Координаты UI и hotspots всегда 1280×720, мир 1536×960. Окно масштабирует виртуальную поверхность с сохранением пропорций и обратным преобразованием координат мыши. Пиксельные поверхности масштабируются без размытия. Текст сглаживается отдельно для чтения.

## Добавление осмотра

В `src/data/investigations.json` добавьте объект:

```json
{
  "title": "Новая сцена",
  "hotspots": [
    {"id": "report", "label": "Отчёт", "rect": [500, 380, 240, 116], "evidence": "report", "art": "papers"}
  ]
}
```

Добавьте `report` в evidence.json (title/source/text/reliability), а в worlds.json — объект kind=investigation со ссылкой scene на ключ сцены. Для временного рендера art поддерживает terminal, papers и board; любую новую область можно добавить без изменения логики, но уникальное изображение потребует расширения Art. UI осмотра занимает верхние 106 и нижние 188 пикселей; hotspots должны оставаться внутри центральной области.

В `rules.json` укажите requires и текст независимого вывода. Все требования трактуются как AND. Частичная цепочка не подтверждается. В dialogues.json choices могут иметь requires, evidence, reply или close.
